# ADR-0025 并行 Agent session 运行时长逐 session 累加

- 状态:Accepted
- 取代:ADR-0013
- 关联:ADR-0003、ADR-0006、PROTOCOL.md §1 §6

## 背景

ADR-0013 规定同一最终身份 `(operator, agent||runtime)` 的多个 session 区间先取并集，使单 Agent
单日时长不超过 24 小时。该口径准确表达身份的墙钟在线时间，但会把并行 Thread/Session 的重叠工作
压成一份，不能体现并行工作量。

产品现在把 Agent 运行时长定位为可观测工作量代理：两个 session 同时有效运行一小时，应贡献两小时。
同时，上一轮已经修复的服务端权威时间、心跳断档和迟到终态规则仍是准确计时的必要前提，不能随聚合
口径一起撤销。

## 决策

- 事件落库的服务端 `recv` 继续是所有时长计算的权威时间；客户端 `ts` 仅供展示。
- `running/started/waiting/blocked` 继续视为存活态；blocked 同时在质量块单列。
- 存活态推荐每 60 秒心跳，stale 阈值继续为 180 秒。连续段只延伸到最后确认心跳；长断档后的存活
  事件从自身 `recv` 开新段，迟到终态不得回填离线期间。
- `session_id` 是可观测并行工作的计时单元。每个 session 独立构造连续段并按 `Asia/Shanghai`
  日边界切分；同一最终身份下各 session 的日秒数直接累加，重叠区间不取并集。
- 单 Agent 单统计日运行时长允许超过 86,400 秒。该指标解释为并行 session 工作量之和，不再解释为
  身份墙钟在线时间或自然日利用率。
- 最终身份卡片仍按 ADR-0006 合并；并行 session 只叠加时长，不增加 Agent 数或同日活跃天数。

## 后果

- ✅ 并行 Thread/Session 的重叠时间会按各自有效心跳区间分别贡献工作量。
- ✅ 服务端时间、断档切段、pending 心跳与迟到终态规则继续防止离线虚增和重复心跳虚增。
- ✅ 无需修改事件 schema 或迁移历史数据；读侧重算即可应用新口径。
- ⚠️ 单日时长可大于 24 小时，不能再用作墙钟在线率或利用率分母。
- ⚠️ 错误地把同一真实工作拆成多个 `session_id` 会重复计量；服务端不做缺乏证据的跨 session 去重。
- ⚠️ 同一 `session_id` 内部不可见的并行线程无法额外计量；如需更细粒度，必须另案扩展采集协议。
